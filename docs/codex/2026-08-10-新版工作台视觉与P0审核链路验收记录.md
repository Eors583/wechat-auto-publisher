## 二、P0 待审核断点根因与修复

### 根因

1. 顶栏通过 `AnalyticsService` 统计所有 `ready_for_review`，包含已经人工确认的文章，而且原 SQL 没有按当前登录账号过滤，因此显示 106。
2. 创作台只汇总最近 20 个批次的 `unconfirmed`，因此显示 10。
3. 任务队列使用正确的当前用户、未归档、未确认文章收件箱，但视觉重构已经移除了独立刷新按钮，渲染函数仍引用不存在的 `refresh_btn`，首次打开时抛出 `NameError`。列表尚未查询，界面只留下初始的“0 条”。

### 修复

- 三处统一使用当前用户、未归档、未确认的审核收件箱口径；本地真实结果为 **86 篇**。
- `AnalyticsService` 的批次、文章、状态和评审统计补上 `owner_user_id` 范围；运营待办使用 `review_inbox_counts()`。
- 顶栏“查看待审核文章”和创作台“继续”都路由到文章级 `review` 收件箱，不再进入批次状态筛选。
- 懒加载任务页可携带 `initial_view`、`initial_bucket` 和 `status_filter`，已挂载任务页也可原地切换。
- 删除 `refresh_btn` 的两处残留引用并增加回归测试。
- `.ops-task-list` 增加统一单列网格轨道，使任务行真实拉伸到设计稿要求的 852px。

- 仅取消任务行“打开审核”的图标；不扩大末列，不修改全局按钮。
- 任务行仍为 x=253、w=852、h=68。
- 按钮仍为 x=1006.984375、y=380.5、w=84、h=39。
- `.q-btn__content` 为 w=58、h=21，`flex: 0 0 21px`、`white-space: nowrap`，水平和垂直居中。
- 重新保存 `actual-tasks-p0-review-inbox.png`，视觉确认 4 个按钮文字均位于描边框内。
- 点击第一条“打开审核”仍正常进入全页审核；成品预览、后台 AI 评审和人工确认入口正常。

同时为 1024×768 折叠侧栏的“创作台、选题雷达、任务队列、公众号”四个图标 tab 增加了相同文字的 `aria-label` 与 `title`。标签继续视觉隐藏，单个 tab 尺寸仍为 55×41，根页面仍为 client/scroll 1024×768。
